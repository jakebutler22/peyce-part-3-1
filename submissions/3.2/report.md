## Model contribution, authority and the exact blocker

Peyce uses a constrained conversation: assistant questions and selected user labels/skips, rather than an open text chat. The provider receives the current received turns, deliberate choice, approved deterministic result and eligible current-question references. It may choose only an opening, relevant reference IDs and a closing. The application inserts exact answer labels and approved copy, rejects extra fields, wrong reasons, skipped/irrelevant references and excessive output, and limits the constructed acknowledgment to 240 characters. It cannot diagnose, score, choose a skill, alter exercise timing, navigate or control support. The current questions and routing remain versioned and unvalidated as a clinical measure.

The authorized configuration is OpenRouter, **`nvidia/nemotron-3.5-lightning:free`**, maximum spend **$0.00**, maximum **ten outbound attempts including failures**, no paid fallback. The exact model was listed with zero input/output pricing. Its advertised parameters exclude native `response_format`, so the request prompts the exact JSON grammar and the application validates it locally; provider-enforced structured output is not claimed. Requests have finite time/input/output limits, no automatic retry, disabled provider fallback, zero-price ceilings and a persistent attempt counter.

Configuration loaded successfully, but that is distinct from a successful request. The first real call returned provider fallback; after adding safe numeric error diagnostics, the second returned **HTTP 401/code 401**. The specifically authorized credential was copied without exposure and its source configuration remained unchanged. Both failed receipts retain actual context and versions; there is **no validated live contribution**. The service returned to mock mode at **2/10 attempts**. A working `OPENROUTER_API_KEY` in ignored `backend/.env`, followed by an authorized successful validated UI request and persisted provenance, is needed to meet this criterion. No secret, raw provider payload, runtime database or personal check-in is published.

Mock acknowledgments demonstrate the integration mechanism and vary with approved context. They do not meet the live-model requirement. Instructor acceptance of button-led conversation also remains a human interpretation question. The restricted model role trades expressiveness for inspectable authority; its added value over fixed rule copy has not been evaluated.
