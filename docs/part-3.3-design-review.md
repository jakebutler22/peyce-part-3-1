## Stored information and control

The implementation stores fictional sessions, versioned snapshots, exact assistant-question/user-answer-or-skip turns, operation receipts, lifecycle events and separately labeled explanation provenance. Current confirmed answers appear once; earlier revisions retain the audit trail without dominating ordinary history. Saved means an acknowledged SQLite write, not an optimistic UI state. Unsaved answers remain local in memory. An explicitly selected balloon colour is the only new local-storage enum (`peyce-balloon-color-v1`); it contains no session/answer data and is separate from the opt-in SQLite record.

Records remain on this computer until explicit history clearing. “Clear history and colour” requires confirmation; it deletes related session data and the remembered colour while preserving outbound-call accounting. A storage-clear failure is reported separately, and a newer colour choice made during deletion is not overwritten. Destructive checks use disposable fictional databases. Provider context is limited to current committed turns, deliberate choice and approved result/eligible references, not earlier sessions or a clinical profile. No credential/raw provider reasoning belongs in public evidence. See the current API/implementation documentation for actual field contracts.

## Findings and remaining evidence

A **genuinely new surprising observation** is S17’s distinction between blocking transport and telling the truth about provenance. The initial controlled API/SQLite run correctly prevented a dispatch at ten simulated attempts but returned `mode=openrouter`, `status=fallback` instead of the requested mock result. The [preserved initial failure](evidence/3.3/deterministic-initial-failure.json) records that mismatch. The correction raises a specific cap condition before dispatch, constructs the existing approved mock grammar, sets `mode=mock` / `status=validated` and persists `validated-mock-live-limit`. Both repeat runs now observe mock provenance and an unchanged ten-attempt fixture counter, with real transport prohibited. No new genuine provider outage or real-ledger mutation is claimed. The finding changed the implementation because no-dispatch alone did not satisfy truthful mock/live separation.

The October 25 observation that HTTP 200 can still yield invalid/truncated model content remains a separate historical finding, not the new surprise above.

A relevant **untested limitation** is natural-human comfort and timing with the face-led flow. Scripted browser waits can verify timing arithmetic and sequences but cannot show whether the words, pace and face labels feel clear or evaluative to a person. Later consented fictional-task usability sessions, including assistive-technology users, could observe reading/decision time, correction success and comprehension; they would still not establish clinical effectiveness. No participants, peer sessions or student personal review are invented.
