## Actual revisions from review

The first schema inspection found that a `finished` breathing snapshot could bypass the 60-second completion guard. The backend now requires completion evidence for completed/finished breathing and ties timing boundaries to instruction/Finish events. The integration tests directly reject both bypasses and pass after the correction.

Controller review identified three integration hazards: failure of the first revision could make later retries impossible; opening history immediately after Finish could outrun its save; changing an explicit visual preference could leave an outdated Saved label. The controller was revised to replay the captured initial operation before later snapshots until the first acknowledgment, await the final save before history refresh, and persist explicit color changes while invalidating obsolete wording. Direct browser initial-failure recovery and saved-history observations substantiate the revised behavior below. This is one documented correction cycle for the identified issues, not an invented service outage.

The authorized free-model catalog did not advertise the native `response_format` parameter. Provider output is untrusted until application validation; provider-native schema enforcement is not claimed. The zero-price maximum, exact model, no paid fallback and attempt guard remain in force.
